# 書架 — 確認方法の是正 v26

## findstr が使えなかった理由

Windowsの `findstr` は**コンソールの文字コード(Shift-JIS)**で検索語を扱いますが、
`bundle.js` は**UTF-8**です。バイト列が一致しないため、
正しくビルドできていても日本語では絶対にヒットしません。

`charset: "utf8"` にしても解決しませんでした。二度も誤った確認方法を案内し、失礼しました。

## 今すぐできる確認(ビルドし直さなくてよい)

ASCII文字なら文字コードの影響を受けません。

```
findstr "2.7em" bundle.js
```

`2.7em` は v25 で追加したカードのレイアウト指定で、それ以前の版には存在しません。

- **長い行が出る** → ビルドは正しい。原因は配信かキャッシュ側
- **何も出ない** → そのフォルダのソースが古い

## 今後のための恒久対策: 版数を画面に表示

`設定` 画面の一番下に **v26** と表示されるようにしました。
これで「いま端末で動いているのはどの版か」が一目で分かります。

推測に頼らず、次の3か所を見比べれば切り分けが完了します。

| 見る場所 | 分かること |
|---|---|
| 設定画面の下部 | 端末で動いている版 |
| `findstr "shoka-build-v26" bundle.js` | 手元のビルドの版 |
| シークレットタブで開いた設定画面 | サーバー上の版 |

例えば「手元=v26 / サーバー=v26 / 端末=v24」なら端末のキャッシュが原因、
「手元=v26 / サーバー=v24」ならアップロードが届いていない、と確定できます。

## デプロイ
`bundle.js?v=26` / `sw.js VERSION="v26"` / `version.js BUILD_LABEL="v26"` の3つを揃えてあります。

```
bundle.js
index.html
sw.js
```
(fonts/ はアップロード済みとのことなので不要です)

## 確認手順
1. `npm run build`
2. `findstr "shoka-build-v26" bundle.js` → 行が出ればOK
3. アップロード
4. Chromeのシークレットタブで開く → 設定画面の下に **v26** と出れば配信成功
5. 通常のアプリでも v26 になっていれば完了(古いままならキャッシュ)
