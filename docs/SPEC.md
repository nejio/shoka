# 書架 (Shoka) 仕様書

対象版: **v36** / 公開URL: https://nejio.github.io/shoka/

この文書は、2026-11-20 時点のソースコードを読んで書いた現行仕様である。
開発上の注意は `CLAUDE.md`、各版の経緯は `docs/history/` を参照。

---

## 1. 目的と設計思想

読書記録のPWA。読んだ本を積み上げ、「読書の毎日を、歴史にする」。

| 方針 | 内容 |
|---|---|
| 積読は負債ではない | 積読は消化すべき負債ではなく**関心の地図**として扱う。読めという圧をかけない |
| 通知しない | 想起は画面内の静かな表示に留める。例外は図書館の返却期限のみ |
| 最小の登録 | 登録フォームは書名と状態だけ。星・著者・ページ数などは「もっと詳しく」の中 |
| 購買導線なし | 書店リンク・価格・セール通知は作らない |
| ロジックはlib | 判断は `src/lib` の純粋関数に置き、テストを書く。componentsは呼ぶだけ |

## 2. 技術構成

| 項目 | 内容 |
|---|---|
| UI | React 18(外部UIフレームワークなし) |
| ビルド | esbuild。成果物は単一の `bundle.js` |
| 認証 | Firebase Authentication(Googleサインイン) |
| データ | Cloud Firestore。オフライン永続化あり |
| 配信 | GitHub Pages |
| オフライン | Service Worker(`sw.js`) |
| 書誌取得 | openBD → Google Books API |
| 対象環境 | スマートフォン主体。本文幅は最大560px。日本語UIのみ |

## 3. 画面構成

起動後は次の順で遷移する。

1. 認証状態の確認中は「読込中」画面を出す。6秒を超える、またはエラー時は「読み込み直す」「サインアウト」を出す
2. 未サインインなら**サインイン画面**(Googleでサインイン)
3. サインイン済みなら**本体(Shell)**。蔵書の購読が始まるまで「読込中」を出す

### 3.1 本体のレイアウト

- ヘッダー: タイトル「書架」、検索ボタン(虫眼鏡)、設定ボタン(歯車)
- 帯: オフライン時と、未送信の書き込みがあるとき(`pending`)に表示する
- エラー表示(赤)と通知表示(金)。通知は4秒で消える
- 本文: 下タブの5画面。タブごとにエラー境界があり、壊れてもそのタブだけが止まる
- 右下の浮動ボタン「記録」
- 下タブ: 暦 / 本棚 / 書斎 / 覚書 / 記録
- 重ねて開く画面: 設定、詳細(Detail)、導入(Intro)、検索(Search)

### 3.2 暦(統計・既定のタブ)

- 切替「自動 / 冊 / 頁」を端末の `localStorage`(`shoka:stats`)に保存する
- 自動判定は、直近60日の読了を月換算して**月10冊以上なら「冊」**、未満なら「頁」を主役にする
- 4枚のカード
  - 冊モード: 連続読書 / 今月 / 今年 / 累計
  - 頁モード: 連続読書 / 今月の読書日 / 今月の頁数 / 累計
- 読書暦(縦型カレンダー)
  - 週が1行、月曜始まり。最新週が最上段で、初期は12週。「さらに」で過去へ伸ばす
  - 濃いマスが読了日、薄いマスが読んだ日。色は主タグの色
  - 1冊の日はその本を開き、複数冊の日は一覧から選ばせる
- 今日の一冊(積読から日替わりで1冊。§6.5)
- 日別ページ数(直近4週)と、月別読了数(直近12か月)。順序は主役に合わせて入れ替える
- 関心の変遷(直近6四半期の、主タグ構成の積み上げバー)
- 蔵書が0冊のときは空状態の案内を出す

### 3.3 本棚

切替「時系列で見る / 主題で見る」。

- **時系列**: 読了本を月ごとの棚に並べる。背表紙の色は主タグ、高さは総ページ数(64〜112px。不明は250ページ相当)。再読には「再」を付ける。初期は6か月分で、「さらに前の棚を見る」で6か月ずつ増える
- **主題で見る(知識の地図)**: 読了本の主題別分布。期間は「全期間 / 直近1年」。副次タグの分布も出す

### 3.4 書斎

積読・読書中・気になる本を、タグの階層で俯瞰する**関心の地図**。

- 分布バー、大分類ごとの群れ(折りたたみ可)、細分での小分けを表示する
- 「タグを整理」から、タグ名の一括変更・統合・削除ができる。旧名称の統合を促す提案もある(§5.3)
- 見送った本は地図から退く

### 3.5 覚書

進捗メモ・読了時の感想・積読の「なぜ気になったか」を、時系列(月ごとの見出し)で並べる。

### 3.6 記録

- 「本の追加」フォーム(QuickAdd)。§4.1
- **読書中**: カードごとに「進捗を記録」「読了にする」。進捗が最終点(100％または総ページ数)に達すると、続けて読了入力に移る
- **読了**: 新しい順の一覧。書名・著者の検索、タグ絞り込み(最大12個)。初期40件で、「さらに表示」で60件ずつ増える

### 3.7 「記録」ボタン(浮動)

「今日の記録」シートを開く。読書中の本ごとに、到達点とひとことメモを今日の日付で保存する。下端の「＋ 本を追加」から記録タブの追加フォームを開く。

### 3.8 詳細(Detail)

本を開いたときの画面。次を編集できる。

- 読始日・読了日(§7.2の検証あり)
- 評価、感想、積読のひとこと、積んだ日
- タグ、保有状況、進捗の単位、足あとのメモ
- 書影の補完、積読→読書中、見送り、見送りからの復帰、削除

### 3.9 設定

| 項目 | 内容 |
|---|---|
| アカウント | メールアドレス、蔵書数と読了数、サインアウト |
| 外観 | テーマの切替 |
| データの書き出し | 蔵書・足あと・タグ・感想・設定をJSONで保存(`shoka-YYYY-MM-DD.json`) |
| アカウントの削除 | 「削除」と入力して確認。取り消し不可 |
| 版数 | 最下部に `BUILD_LABEL` を表示。端末で動いている版の確認に使う |

### 3.10 導入(Intro)

初回のみ表示する。蔵書が既にある利用者には出さず、既読として扱う。

## 4. 機能仕様

### 4.1 本の登録

状態は「積読 / 読書中 / 読了」から選ぶ。既定は「読書中」。

| 状態 | 必須 | 任意(もっと詳しく) |
|---|---|---|
| 積読 | 書名 | 積んだ日、なぜ気になったか、気になる本(未所持) |
| 読書中 | 書名 | 読始日(既定は今日) |
| 読了 | 書名、読了日(既定は今日) | 読始日、評価、感想 |

共通の任意項目: タグ(最大5)、著者、ページ数、読む形式(紙 / 電子書籍とサービス名)。

**書誌の自動入力**

- バーコード読み取り(`BarcodeDetector`、なければ ZXing へフォールバック)。書籍のバーコード(978/979)のみ受け付け、書籍JANの下段(192〜)は無視して読み取りを続ける
- 書名検索(著者名の併用も可)。結果から著者で絞り込める。蔵書にいる著者を候補に出す
- ISBNを直接入力しても引ける
- 電子書籍にはバーコードがないため、書名検索を案内する

### 4.2 重複の扱い

積読・読書中・見送りの中に同じ本があるとき、新規作成せず状態を進める。読了本は対象外で、再読を許容する。

- 判定: 双方にISBNがあればISBN一致。なければ書名の完全一致(前後の空白は無視)
- 読了として登録 → 既存の本を読了にする(足あとは引き継ぐ)
- 読書中として登録 → 積読・見送りを読書中に移す。すでに読書中ならエラー
- 積読として登録 → 気になる本だったものは入手済みにする。見送りは積読に戻す。それ以外はエラー

### 4.3 進捗(足あと)

- 到達点方式: `sessions` に「日付と到達ページ(または％)」を追加する。日付順に並べ替える
- 前回の到達点より先でなければならない。上限は、％なら100、ページなら総ページ数(不明なら上限なし)
- 単位は本ごとに持つ。未設定なら、電子書籍は％、それ以外はページ
- 単位を変えても、記録済みの足あとは消さない
- ひとことメモは任意(2000字まで)。空なら保存しない。あとから編集できる
- 読了時、読了日に到達記録がなく総ページ数(または100％)が分かるときは、最終点の足あとを補う。暦に読了日を刻むため

### 4.4 読了

- 読了日(必須)、評価(任意)、感想(任意・2000字まで)
- 読始日が無い本(積読から直接読了)は、読了日で補う
- 同名の読了本が既にあれば `reread: true`(再読)とする

### 4.5 保有状況(holding)

読書の進行(`status`)とは別の軸。`null` は「紙で所有」を意味する。

| type | 意味 | 付随情報 |
|---|---|---|
| `paper` | 紙で所有(保存時は `null`) | なし |
| `ebook` | 電子書籍 | `service`(40字まで。主要8サービスは候補に出す) |
| `library` | 図書館 | `returned`、`dueDate`(未返却のときのみ) |
| `wanted` | 気になる本 | なし。まだ入手していない |
| `released` | 手放した | なし |

- 「手元にない」本: 気になる本、手放した本、返却済みの図書館本
- 「出ていった」本(`isGone`): 手放した本と返却済みの図書館本。気になる本は含まない
- 返却期限: 残り日数を表示する。3日以内または超過で強調する。ラベルは「返却 M/D」「返却は明日」「返却は今日」「返却期限すぎ」
- 「入手済みにする」で `holding` を `null`(紙で所有)に戻す

### 4.6 見送り

積読を `setaside` にする。蔵書には残るが、関心の地図からは退く。復帰すると積読に戻る。

### 4.7 評価

1〜5の整数。それ以外は `null`(未評価)。`0` も未評価として扱う。

### 4.8 タグ

§5.3 を参照。変更は詳細画面から行い、タグ名の一括変更・削除は書斎から行う。

### 4.9 書影の補完

ISBNで引き、書影がなければ書名で検索して、書影のある最初の結果を使う。ISBNが無い本には、見つかったISBNも補う。

### 4.10 全体検索

書名・著者・タグ・メモ(進捗メモと総括メモ)を横断して検索する。

- 空白区切りの語はすべて含む本だけを返す(AND条件)。大文字小文字と前後空白は無視する
- 書名に一致した本を先に、次いで新しい順に並べる
- どのメモが一致したかを添え、一致箇所の前後を切り出して表示する

呼び出し口は、ヘッダーの検索ボタン(虫眼鏡。設定ボタンの左)。全画面で開き、結果を選ぶと閉じて、その本の詳細を開く。

### 4.11 アカウントの書き出しと削除

- 書き出し: `{app, schema: 2, exportedAt, bookCount, prefs, books}`。タイムスタンプはISO文字列に直す
- 削除は次の順で行う(認証を先に消すと、データを消す権限を失うため)
  1. 蔵書を450件ずつ削除
  2. ユーザー設定を削除
  3. 認証アカウントを削除。最近サインインしていなければ再認証する
- オフラインでは削除できない。再認証に失敗した場合、蔵書は削除済みである旨をメッセージで伝える

## 5. データ仕様

### 5.1 Firestore

| パス | 内容 |
|---|---|
| `users/{uid}` | 利用者設定(`onboarded`、`updatedAt`) |
| `users/{uid}/books/{id}` | 1冊 = 1ドキュメント |

セキュリティルール(`firestore.rules`): どちらも、本人(`request.auth.uid == uid`)のみ読み書きできる。

蔵書は `createdAt` の降順で購読する(単一フィールドのため複合インデックス不要)。表示順の細かい制御は各画面でクライアント側ソートする。

### 5.2 本のドキュメント

| 項目 | 型 | 内容 |
|---|---|---|
| `title` | string | 必須、200字まで |
| `author` | string | 100字まで |
| `tags` | string[] | 先頭が主タグ(色に使う)。最大5、1つ20字まで。空なら `["未分類"]` |
| `tag` | string | 旧項目。`tags[0]` を併記して維持 |
| `pages` | number \| null | 1〜10000の整数 |
| `isbn` | string \| null | ISBN-10/13。ハイフンと空白は除去 |
| `coverUrl` | string \| null | 書影URL |
| `status` | string | `stacked` / `reading` / `finished` / `setaside` |
| `start` | `YYYY-MM-DD` \| null | 読始日 |
| `end` | `YYYY-MM-DD` \| null | 読了日 |
| `stackedAt` | `YYYY-MM-DD` \| null | 積んだ日 |
| `rating` | 1〜5 \| null | 未評価は `null` |
| `note` | string | 感想、または積読の「なぜ気になったか」。2000字まで |
| `sessions` | `[{date, toPage, memo?}]` | 読書の足あと。日付順 |
| `holding` | `null` \| `{type, ...}` | §4.5 |
| `progressUnit` | `page` \| `percent` \| null | 未設定なら保有状況から判定 |
| `reread` | boolean | 再読か |
| `createdAt` / `updatedAt` | Timestamp | サーバー時刻 |

日付は文字列 `YYYY-MM-DD`(ローカル日付)で持つ。`toISOString()` はUTC変換で日本時間では1日ずれるため使わず、`dates.js` の `isoLocal` を使う。

### 5.3 タグ分類

内容の軸の大分類10に、形式の例外2を足した二層構造(細分は計93)。NDC(日本十進分類法)を読書記録向けに改めたもの。

| 区分 | 大分類 |
|---|---|
| 内容(10) | 小説 / エッセイ・紀行 / 歴史 / 政治・社会 / 経済・経営 / 科学・数学 / 技術・工学 / 哲学・思想 / 芸術・文化 / 実用・生活 |
| 形式(2) | 漫画 / 児童書・絵本 |

- 形式を別に立てる理由: 1冊あたりの所要時間が桁違いで、ページ数と読書ペースの統計を歪めるため
- 自作タグも使える。大分類にも細分にも属さない自作タグは、独立した群れとして扱う
- 色はタグ名から決定的に割り当てる(16色の落ち着いた色相)。タグを増やしても既存の色は変わらない
- 旧タグ名の対応表(`RENAMED`)を持つ。既存データは書き換えず、書斎の「タグを整理」で統合を促す
- 旧形式の `tag` 単数のみのデータも `getTags` で読める

## 6. 主要ロジック

### 6.1 集計(`stats.js`)

- 日別マップ: 日付 → `{finished: [本], reads: [本]}`。1日に複数冊ありうるため、読了は配列で持つ
- 日別ページ数: 足あとの差分を合算する。足あとのない1日読了(読始日と読了日が同じ)は総ページ数を加える
- ％で記録した本は、総ページ数が分かるときだけ実ページに換算する。不明なら0(読書日にのみ数える)
- 連続読書: 今日から遡って、読書日(足あと or 読了のある日)が途切れるまでの日数
- 月ペース: 直近60日の読了数 ÷ 2

### 6.2 進捗(`progress.js`)

`progressUnit` / `progressMax` / `lastProgress` / `progressPct` / `reachedEnd` / `deltaToPages` を提供する。

### 6.3 地図(`study.js`)

- 本の所属: 主タグから順に見て最初の大分類。なければ細分の親。どちらもなければ先頭タグ(または未分類)
- 各本はちょうど1回だけ現れる(分布の合計は100%)
- 書斎の地図の対象: 積読・読書中・気になる本。手放した本と返却済みの図書館本は外す
- 分布バーは手元にある本のみ(気になる本を混ぜると分布が歪むため)
- 知識の地図: 読了本のみ。期間指定は読了日で絞る

### 6.4 書誌の正規化(`biblio.js`)

- ISBN-10はISBN-13に変換する
- タグ推定の優先順は、openBDのCコード(下2桁の内容分類 → 2桁目のジャンル)、次にカテゴリ・書名のキーワード
- 取得結果は共通形 `{isbn, title, author, pages, coverUrl, publisher, published, tag, source}`

### 6.5 日替わりの一冊・想起

- 今日の一冊: 積読(気になる本・出ていった本を除く)から、日付のハッシュで決定的に1冊を選ぶ。同じ日は何度開いても同じ本
- 想起: 読了直後に、同じタグの積読を最大3冊、通知帯に静かに出す(例: 「書斎に近い関心の本が2冊あります」)

### 6.6 書誌API(`biblioApi.js`)

- タイムアウトは8秒。HTTP 429のときは1回だけ待って再試行し、それでも駄目なら混雑のメッセージを返す
- ISBN検索: openBD → Google Books の順
- 書名検索: Google Books(日本語・国は JP)。`config.js` の `GOOGLE_BOOKS_KEY` があればキーを付ける

## 7. 入力検証(`validate.js`)

### 7.1 共通

| 項目 | 規則 |
|---|---|
| 書名 | 必須(エラー「書名は必須です」)。200字まで |
| ISBN | 形式 `^(97[89])?\d{9}[\dX]$`。不正ならエラー |
| ページ数 | 1〜10000の整数。範囲外は `null` |
| 日付 | `YYYY-MM-DD` |

### 7.2 登録・更新ごと

- 読了登録: 読了日が必須。読始日が無ければ読了日で補う。読始日が読了日より後ならエラー
- 読書中の登録: 読始日が必須
- 進捗: 到達点は正の整数で、前回より大きいこと。上限は§4.3
- 日付更新: 読始日が読了日より後ならエラー

## 8. オフラインとPWA

- Firestoreのオフライン永続化を使う。オフライン中の記録は端末に保存され、接続時に自動で同期する
- 未送信の書き込みを持つ本には、一覧で「⏳」を付ける
- 画面上部の帯: オフライン時は「オフライン — 記録は端末に保存され…」、オンラインで未送信があるときは「同期中… 未送信 N件」
- Service Worker
  - 事前取得するのは `./`、`./index.html`、`./manifest.json` のみ
  - 画面遷移はネット優先。オフラインのときだけキャッシュした `index.html` を返す
  - `bundle.js`・フォント・アイコンは、実際に読み込めたときに保存する(事前取得しない)。事前取得すると、`sw.js` だけ先にデプロイされた瞬間に古い中身が新しい名前で固定されるため
  - 自オリジンのGETのみを扱い、Firebaseなどの通信には触れない
  - キャッシュ名は `shoka-{VERSION}`。有効化時に、他のキャッシュを削除する

## 9. 版管理とデプロイ

版数は3箇所を**同じ番号に**上げる。1つでも漏れると反映されない。

| ファイル | 該当箇所 |
|---|---|
| `index.html` | `<script src="bundle.js?v=NN">` |
| `sw.js` | `const VERSION = "vNN"` |
| `src/version.js` | `BUILD` と `BUILD_LABEL` |

- 変更後は `npm test` と `npm run build` を必ず実行する
- デプロイは `bundle.js` / `index.html` / `sw.js` をGitHubへpushする。`fonts/`、`icons/`、`manifest.json` は変更時のみ
- 詳細は `docs/DEPLOY.md`、`docs/UPDATE_FLOW.md`

## 11. 既知の制約と未確認事項

- データはFirestoreに置く。端末をまたぐ同期は、Googleアカウント単位である
- 書き出し(JSON)はあるが、**取り込み(インポート)の機能は現行コードに見当たらない**
- 利用者数が増えた場合のFirestore読み取り量: 蔵書全件をリアルタイム購読している。蔵書が数千冊規模になったときの挙動は未検証
- 画面の細部(詳細画面の項目順、書斎の操作、導入ページの文言など)は、この仕様書では要点のみ記している。変更時は該当コンポーネントを読むこと
