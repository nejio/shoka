# 書架 — 反映されない問題の修正 v26

## 私の診断ミスについて

`findstr "頁数" bundle.js` で確認するよう案内しましたが、**この方法は誤りでした**。

esbuildは既定で**非ASCII文字を `\u9801\u6570` の形式にエスケープして出力**します。
つまり正しくビルドされていても、日本語では絶対にヒットしません。
それを根拠に「アップロードされていない」と判断したのは私の誤りです。

### 対応
`build.mjs` に `charset: "utf8"` を追加しました。
今後は日本語がそのまま出力されるので、検索での確認が効きます
(副産物として出力が12KB小さくなりました)。

## 反映されなかった本当の原因(推定)

Service Workerの作りに問題がありました。

これまでは `bundle.js?v=N` を**事前取得(precache)**していました。
この方式には次の落とし穴があります。

1. `sw.js` と `index.html` を先にアップロードする
2. その時点でService Workerが入れ替わり、`bundle.js?v=25` を取りに行く
3. しかしサーバー上の `bundle.js` はまだ古い
4. **古い中身が「v25」という名前でキャッシュに焼き付く**
5. 以後、いくら正しい `bundle.js` をアップロードしても、
   端末はキャッシュの古い中身を返し続ける

アップロードの順序次第で、この状態に陥ります。

### 対応
**事前取得をやめました。**

- 事前取得するのは `index.html` と `manifest.json` だけ(オフライン起動用の最小限)
- `bundle.js`・フォント・アイコンは「**実際に読み込めた時に保存する**」方式に変更
- `bundle.js?v=N` は版が変わると別URLになるので、更新時は必ず取り直される

これでアップロードの順序に関係なく、正しく更新されるようになります。

## 今回の確認方法

デプロイ後、**Chromeのシークレットタブ**で開いてください。
シークレットではService Workerが動かないため、サーバー上の実物がそのまま表示されます。

- シークレットで新しい表示になる → サーバーは正常。端末のキャッシュが原因
- シークレットでも古い → サーバー上のファイルが古い

### ビルドの確認(修正版)
```
npm run build
findstr "頁数" bundle.js
```
`charset: "utf8"` にしたので、今度は**正しくヒットします**。
何も出なければビルドが失敗しているか、フォルダが違います。

## 端末に残った古いキャッシュの消し方

一度おかしくなったキャッシュは、版を上げれば消えます(v26で新しい名前になり、
古いキャッシュは破棄されます)。それでも残る場合は:

Chrome → 設定 → サイトの設定 → 保存されているデータ → `nejio.github.io` → 削除
インストール済みPWAは、一度アンインストールして入れ直すのが確実です。
