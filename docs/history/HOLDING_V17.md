# 書架 — 保有状況 v17

## 設計

保有状況は、読書の進行(status)とは**直交する軸**として独立したフィールドに持つ。
「読了かつ売却済み」「積読かつ図書館」が普通に成立するため、statusに値を足すのは誤り。

```
holding: null | {
  type: "ebook" | "library" | "released",
  service?: string,    // 電子書籍のサービス名
  dueDate?: string,    // 図書館の返却期限
  returned?: boolean,  // 図書館の返却済みフラグ
}
```

**未設定(null) = 紙で所有**。バーコードで登録できる本は物理的に持っているので、
既定値にすることで大半の本は設定不要になる。

## 使い方

詳細画面の「保有状況を記録 ▾」から設定する。**登録フォームには出さない**ので、
使わない人の目には一切入らない。

- **紙で所有**(既定) … 何も表示されない
- **電子書籍** … Kindle / 楽天Kobo / BOOK☆WALKER / Apple Books /
  Google Play ブックス / honto / ebookjapan / DMMブックス から選択、自由入力も可
- **図書館** … 返却期限を設定でき、返却したらチェックを入れる
- **手放した** … 売却・譲渡・処分

## 返却期限の扱い

「読めというプレッシャーは与えない」という原則は維持したまま、
返却期限だけは静かに表示する。これは読書の催促ではなく、
ユーザーが自分で負った実務的な約束のため。

- 表示場所: 読書中カード、書斎のタイル、詳細画面
- 表示内容: 「返却 8/3」「返却は明日」「返却は今日」「返却期限すぎ」
- 3日以内または超過で金色になる(それ以外は目立たない灰色)
- **通知は出さない**

## 地図への影響

| | 手放した / 返却済み |
|---|---|
| 関心の地図(書斎) | **外れる**。手元にない本は「これから読む予定」ではない |
| 本棚・知識の地図 | **残る**。所在は変わっても、読んだ事実は変わらない |

これはテストで固定してある(`知識の地図: 手放しても読書履歴は残る`)。

## 積読 × 図書館 という組み合わせ

積読の思想「読まなくていい、積んでおけ」は**所有している本にのみ成立する**。
図書館の本には返却期限があるので、同じ積読でも性質が正反対になる。

- 積読 × 所有 = 急がなくてよい(ビオトープ)
- 積読 × 図書館 = 期限がある(このアプリで唯一、締切を持つ項目)

## デプロイ
`bundle.js?v=17` / `sw.js VERSION="v17"`。

## スモークテスト
- [ ] 詳細画面に「保有状況を記録」が出る(未設定時は点線の控えめな表示)
- [ ] 電子書籍を選ぶとサービス選択が出る。自由入力もできる
- [ ] 図書館を選ぶと返却期限を設定できる
- [ ] 期限が読書中カード・書斎タイル・詳細に静かに表示される
- [ ] 3日以内になると金色になる
- [ ] 「返却済み」にすると期限表示が消える
- [ ] 「手放した」にすると書斎の地図から消える
- [ ] 手放した読了本が本棚・知識の地図に残っている
- [ ] 保有状況を設定していない本には何も表示されない
