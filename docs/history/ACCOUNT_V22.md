# 書架 — 設定画面とアカウント削除 v22

## 背景

App Store / Google Play はいずれも、**アプリ内からアカウントと全データを削除できること**を
必須要件にしている。認証方式(Appleサインイン等)より優先度の高いリリースブロッカーのため、
先に実装した。

## 1. 設定画面を新設

ヘッダー右の「設定」から開く全画面。散らばっていた項目をここに集約した。

| 項目 | 内容 |
|---|---|
| アカウント | メールアドレス、蔵書数・読了数、サインアウト |
| 外観 | テーマ(白 / 黒)。ヘッダーの循環ボタンから移設 |
| データの書き出し | 全記録をJSONで保存 |
| アカウントの削除 | 下記 |

## 2. データの書き出し

蔵書・読書の足あと・タグ・感想・保有状況をすべて含むJSONを端末に保存する。
ファイル名は `shoka-YYYY-MM-DD.json`。

Firestoreのタイムスタンプは日時文字列に変換してあるので、
他のツールでも読める形式になっている。

読書の記録は年単位で積み上げた個人史であり、いつでも手元に取り出せるべき、
という考えによる。

## 3. アカウントの削除

### 確認の強度
不可逆かつ全消去のため、二段タップでは不十分と判断し、
**「削除」と入力させる**方式にした。あわせて消えるもの
(蔵書◯冊・読書暦・すべての感想と足あと)を明示し、
書き出しを勧める一文を添えている。

### 削除の順序
1. 蔵書(`users/{uid}/books`)を450件ずつ分割削除 … 進捗を冊数で表示
2. ユーザー設定(`users/{uid}`)を削除
3. 認証アカウントを削除

認証を先に消すとデータを消す権限を失うため、この順序でなければならない。
Sparkプラン(無料)ではCloud Functionsが使えないため、すべて端末側で実行する。
Firestoreの一括書き込み上限(500)に合わせて450件ずつに分割し、
毎回必要な分だけ読むので、蔵書が数百冊あっても重くならない。

### 本人確認(再認証)
Firebaseは削除に「最近サインインしたこと」を要求する。
条件を満たさない場合はGoogleの確認画面を出す。
PWAとしてインストールした環境ではポップアップが使えないことがあるため、
その場合は「一度サインアウトしてサインインし直してください」と案内する。

### オフライン
削除には通信が必要。オフラインでは実行前に弾く。

## 今後の認証方式について(未着手)

| 方式 | 状況 |
|---|---|
| Apple サインイン | iOS配信するなら**必須**(審査ガイドライン4.8)。Apple Developer Program $99/年 |
| メール+パスワード | 外部依存のない受け皿として推奨 |
| 匿名認証+昇格 | 初回離脱の対策。データ消失リスクの導線設計が要る |
| LINE / Yahoo!JAPAN | Firebase非対応。Cloud Functions等が必要なため当面見送り |

Google Play Console は $25(買い切り)。
iOS版を出さない判断なら、Appleサインインの実装自体が不要になる。

## デプロイ
`bundle.js?v=22` / `sw.js VERSION="v22"`。

## スモークテスト
- [ ] ヘッダーの「設定」で設定画面が開く
- [ ] テーマを白/黒で切り替えられる(ヘッダーの循環ボタンは廃止)
- [ ] 「すべての記録を書き出す」でJSONがダウンロードされ、中身が正しい
- [ ] 「アカウントを削除する」→ 確認欄が出る
- [ ] 「削除」以外を入力すると実行ボタンが押せない
- [ ] 削除中に冊数の進捗が出る
- [ ] 削除後、サインイン画面に戻る
- [ ] 機内モードでは削除できない旨が出る

※ 削除のテストは**取り消せません**。試す場合は必ず別のアカウントで行ってください。
